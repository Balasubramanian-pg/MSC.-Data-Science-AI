# 8.4.8. Critical Trade-offs

### 8.1 The "Black Box" Risk

Automated features can become abstract. A feature named `MEAN(STD(ROLLING_SUM(transactions.amount)))` is mathematically well-defined but difficult to explain to stakeholders who ask *why* a customer is flagged as high credit risk.

Human-defined metrics like "Debt-to-Income Ratio" carry intuitive meaning. Automated features often do not.

### 8.2 Memory and Computation

Both DFS and TSFresh can generate massive feature matrices.

Suppose Featuretools explores all possible aggregations across a relational schema. The number of candidate features grows combinatorially with:

- the number of entities

- the depth of stacking operations

- the number of aggregation functions

If candidate features number in the millions, local RAM may be insufficient. Implement these processes in batches or on distributed systems (like Spark) rather than in local memory.

### 8.3 Domain Expertise

These tools are **force multipliers, not replacements**.

They will find relationships you missed, but they will never understand business context. For example, no automated tool knows that a specific date is a public holiday with predictable effects on sales.

Use automated tools to **explore**, but use domain knowledge to **curate** the final feature set.
