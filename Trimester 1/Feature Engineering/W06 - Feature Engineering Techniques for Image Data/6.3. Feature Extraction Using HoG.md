# 6.3. Feature Extraction Using Histogram of Oriented Gradients (HOG)

## 6.3.1. From Raw Pixels to Structural Descriptors

Raw pixel intensity is rarely an optimal feature for object detection because it is highly sensitive to noise, illumination, and exact spatial positioning. In a digital image of dimensions $$H \times W$$, each pixel can be viewed as an individual feature:

$$
X = \{x_1, x_2, \dots, x_N\} \quad \text{where} \quad N = H \times W
$$

This high-dimensional representation is typically sparse in meaningful structural information and computationally expensive. To identify objects, we require a representation that is invariant to illumination and slight deformations. The Histogram of Oriented Gradients (HOG) achieves this by encoding the distribution of local intensity gradients rather than absolute intensity values.

## 6.3.2. Theoretical Foundations of Gradient Fields

The HOG descriptor operates on the principle that the local shape and appearance of an object are characterized by the distribution of intensity gradients.

### 1. Gradient Computation
For each pixel $$(x, y)$$, we compute horizontal and vertical gradients using derivative masks:

$$
g_x(x,y) = I(x+1, y) - I(x-1, y)
$$

$$
g_y(x,y) = I(x, y+1) - I(x, y-1)
$$

These represent the rate of change of intensity across the image grid.

### 2. Magnitude and Orientation
From these components, we derive the gradient magnitude ($$m$$) and orientation ($\theta$):

$$
m(x,y) = \sqrt{g_x(x,y)^2 + g_y(x,y)^2}
$$

$$
\theta(x,y) = \text{atan2}(g_y(x,y), g_x(x,y))
$$

The magnitude $$m(x,y)$$indicates the edge strength, while$$\theta(x,y)$$ indicates the direction of the edge.

## 6.3.3. The Four-Stage Computational Workflow

The construction of the final feature vector follows a strict hierarchical process designed to balance local detail with global robustness.

### 1. Gradient Orientation Binning
The image is subdivided into small spatial regions called cells, typically $$8 \times 8$$pixels. For each cell, the algorithm creates a histogram of orientation bins (e.g., 9 bins covering$$0^\circ$$ to $$180^\circ$$). 

>[!Note]
> Each pixel in the cell contributes its gradient magnitude $$m(x,y)$$as a "vote" to the histogram bin corresponding to its orientation$$\theta(x,y)$$. This binning process provides robustness to minor spatial shifts.

### 2. Block Normalization
To mitigate the effects of illumination intensity, such as shadows or overexposure, cells are grouped into larger, overlapping windows called blocks (e.g., $$2 \times 2$$ cells). The local histograms are concatenated and normalized.

### 3. Normalization Formula
The block vector $$v$$ is normalized using the L2-norm:

$$
v_{normalized} = \frac{v}{\sqrt{\|v\|^2_2 + \epsilon^2}}
$$

where:

- $$\|v\|_2$$is the L2-norm:$$\sqrt{\sum_{i=1}^{n} v_i^2}$$
- $$\epsilon$$ is a small constant (the "soft-clipping" value) added to ensure numerical stability against division by zero.

### 4. Feature Vector Concatenation
The final HOG feature vector is produced by concatenating all normalized block histograms. This resulting vector serves as a robust, high-dimensional signature of the image's structural edges.

## 6.3.4. Parametric Sensitivity and Mathematical Trade-offs

The performance of a HOG-based model is heavily dependent on three primary hyper-parameters:

| Parameter | Mathematical Role | Effect of Increase |
|:---:|:---:|:---:|
| `orientations` | Number of angular histogram bins | Higher precision in edge directionality |
| `pixels_per_cell` | Spatial resolution of the descriptor | Smaller values increase detail/noise |
| `cells_per_block` | Normalization region size | Larger regions normalize over more context |

>[!Warning]
> Increasing the `orientations` parameter or decreasing `pixels_per_cell` drastically increases the length of the feature vector. This can lead to the "curse of dimensionality," where the complexity of the machine learning model exceeds the available training data, causing overfitting.

## 6.3.5. HOG in the Context of Machine Learning

Once the feature vector is constructed, it is typically fed into a linear classifier, such as a Support Vector Machine (SVM).

### 1. The Decision Function
For an input image represented by a HOG vector $$X_{HOG}$$, the SVM classification score is:

$$
f(X_{HOG}) = w^T X_{HOG} + b
$$

where:

- $$w$$ = learned weight vector
- $$b$$ = bias term

### 2. HOG vs. Convolutional Neural Networks (CNNs)
While CNNs perform feature extraction and classification simultaneously:

$$
\text{CNN Feature} = \sigma(W_{conv} * I + b)
$$

HOG is a deterministic, manual feature extractor. The layers in a CNN often learn filters that replicate the behavior of HOG (detecting gradients and edges), but HOG remains a powerful, computationally efficient baseline when labeled training data is limited.

## 6.3.6. Summary Table: HOG Configuration

To maintain technical consistency, use the following guidelines for standard object detection tasks:

| Configuration Variable | Standard Range | Rationale |
|:---:|:---:|:---:|
| `orientations` | 8 - 12 | Standard for capturing dominant edges |
| `pixels_per_cell` | 8x8 | Balances structural detail vs noise |
| `cells_per_block` | 2x2 | Provides optimal illumination normalization |

HOG transforms raw pixel matrices into structural edge representations, providing the backbone for traditional computer vision and serving as the mathematical inspiration for modern convolutional layer architectures.
