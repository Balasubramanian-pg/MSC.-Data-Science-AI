# 7.0. Proximity Measures

## 7.0.1. Introduction to Proximity Analysis

Proximity analysis forms the mathematical backbone of many data mining and machine learning algorithms. Before we can group, classify, or recommend items, we must first quantify how close or far apart they are in the feature space.

### 7.0.1.1. The Concept of Proximity

Proximity is a numerical measure that quantifies the degree of closeness or separation between two data objects. 

>[!Note]
> **Proximity** is the foundational metric that translates abstract data points into a geometric space where relationships can be mathematically evaluated.

### 7.0.1.2. Similarity vs Dissimilarity

We must strictly distinguish between similarity and dissimilarity, as they behave inversely.

**Similarity** is a numerical measure of how alike two objects are. Higher values indicate greater similarity. It is typically normalized to the range $$[0, 1]$$.

**Dissimilarity**, often called distance, is a numerical measure of how different two objects are. Lower values indicate greater similarity. The minimum distance is typically zero, indicating identical objects.

To emphasize the inverse relationship, we state the fundamental property:

$$
\text{Similarity} \propto \frac{1}{\text{Dissimilarity}}
$$

## 7.0.2. Proximity Measures for Numeric Attributes

Numeric attributes possess a meaningful order and equal intervals, allowing us to use geometric distance metrics. The choice of metric depends on the shape of the data distribution and the presence of correlations.

### 7.0.2.1. Euclidean Distance

The **Euclidean distance** is the most common measure of dissimilarity for continuous numeric attributes. It represents the straight-line distance between two points in a $$d$$-dimensional space.

The formula for the Euclidean distance between objects $$x$$ and $$y$$ is:

$$
d(x, y) = \sqrt{\sum_{k=1}^{d} (x_k - y_k)^2}
$$

where:
- $$d(x, y)$$ = Euclidean distance
- $$x_k$$ = value of the $$k$$-th attribute for object $$x$$
- $$y_k$$ = value of the $$k$$-th attribute for object $$y$$
- $$d$$ = number of dimensions (attributes)

To emphasize the core Euclidean distance formula, we restate it:

$$
d(x, y) = \sqrt{\sum_{k=1}^{d} (x_k - y_k)^2}
$$

### 7.0.2.2. Manhattan and Minkowski Distances

The **Manhattan distance**, also known as the L1 norm or city-block distance, measures the distance between two points by only moving along axes at right angles.

$$
d(x, y) = \sum_{k=1}^{d} |x_k - y_k|
$$

The **Minkowski distance** is a generalized metric that encompasses both Euclidean and Manhattan distances:

$$
d(x, y) = \left( \sum_{k=1}^{d} |x_k - y_k|^r \right)^{1/r}
$$

where $$r$$ is a positive integer. When $$r = 1$$, the Minkowski distance reduces to the Manhattan distance. When $$r = 2$$, it reduces to the Euclidean distance.

### 7.0.2.3. Mahalanobis Distance

When numeric attributes are correlated or have different variances, Euclidean distance can be misleading. The **Mahalanobis distance** accounts for the covariance structure of the data.

$$
d(x, y) = \sqrt{(x - y)^T \Sigma^{-1} (x - y)}
$$

where:
- $$\Sigma^{-1}$$ = inverse of the covariance matrix of the dataset
- $$(x - y)^T$$ = transpose of the difference vector

This metric effectively scales the distance by the variance and removes the effect of correlation, making it invariant to the scale of the variables.

## 7.0.3. Proximity Measures for Binary Attributes

Binary attributes take only two values, typically 0 and 1. The choice of proximity measure depends on whether the attribute is symmetric or asymmetric.

### 7.0.3.1. Simple Matching Coefficient

For symmetric binary attributes, where both 0 and 1 carry equal weight, we use the **Simple Matching Coefficient (SMC)**. 

Let us define the contingency table counts:
- $$M_{11}$$ = number of attributes where both $$x$$ and $$y$$ are 1
- $$M_{00}$$ = number of attributes where both $$x$$ and $$y$$ are 0
- $$M_{10}$$ = number of attributes where $$x$$ is 1 and $$y$$ is 0
- $$M_{01}$$ = number of attributes where $$x$$ is 0 and $$y$$ is 1

The SMC is defined as:

$$
\text{SMC}(x, y) = \frac{M_{11} + M_{00}}{M_{11} + M_{00} + M_{10} + M_{01}}
$$

### 7.0.3.2. Jaccard Coefficient

For asymmetric binary attributes, the presence of a feature (1) is much more informative than its absence (0). In such cases, we ignore the $$M_{00}$$ matches and use the **Jaccard coefficient**.

The Jaccard coefficient is defined as:

$$
J(x, y) = \frac{M_{11}}{M_{11} + M_{10} + M_{01}}
$$

To emphasize the Jaccard formula, we restate it:

$$
J(x, y) = \frac{M_{11}}{M_{11} + M_{10} + M_{01}}
$$

## 7.0.4. Proximity for Nominal, Ordinal, and Mixed Attributes

Real-world datasets rarely consist of a single attribute type. We must adapt our proximity measures to handle categorical, ranked, and mixed data structures.

### 7.1 Nominal Attributes

For nominal attributes with multiple categories, we can use a simple matching approach. If the nominal attribute has $$V$$ valid categories, we can encode it using binary variables or simply assign a distance of 0 if the categories match and 1 if they differ.

### 7.2 Ordinal Attributes

Ordinal attributes have a meaningful order. The most robust approach is to replace the ordinal values with their ranks. 

Let $$r_{ik}$$ be the rank of the $$i$$-th object for the $$k$$-th ordinal attribute. We then map these ranks to the interval $$[0, 1]$$:

$$
z_{ik} = \frac{r_{ik} - 1}{R_k - 1}
$$

where $$R_k$$ is the total number of possible ranks for the $$k$$-th attribute. Once mapped, we can treat them as interval numeric attributes and apply standard distance metrics.

### 7.3 Mixed-Type Attributes

When a dataset contains a mixture of numeric, nominal, and ordinal attributes, we compute the distance for each attribute type separately and then combine them.

The overall dissimilarity between objects $$i$$ and $$j$$ is:

$$
d(i, j) = \frac{\sum_{k=1}^{d} \delta_{ijk} d_{ijk}}{\sum_{k=1}^{d} \delta_{ijk}}
$$

where:
- $$\delta_{ijk} = 1$$ if the $$k$$-th attribute is valid for both objects, and 0 otherwise
- $$d_{ijk}$$ is the normalized distance contribution of the $$k$$-th attribute

## 7.0.5. Cosine Similarity for High-Dimensional Data

In text mining and information retrieval, datasets are often represented as high-dimensional, sparse vectors. In such spaces, the magnitude of the vector (document length) is less important than the orientation.

**Cosine similarity** measures the cosine of the angle between two non-zero vectors.

The formula for cosine similarity is:

$$
\text{Cosine}(x, y) = \frac{x \cdot y}{\|x\| \|y\|} = \frac{\sum_{k=1}^{d} x_k y_k}{\sqrt{\sum_{k=1}^{d} x_k^2} \sqrt{\sum_{k=1}^{d} y_k^2}}
$$

where:
- $$x \cdot y$$ = dot product of vectors $$x$$ and $$y$$
- $$\|x\|$$ = Euclidean norm (magnitude) of vector $$x$$

To emphasize the cosine similarity formula, we restate it:

$$
\text{Cosine}(x, y) = \frac{\sum_{k=1}^{d} x_k y_k}{\sqrt{\sum_{k=1}^{d} x_k^2} \sqrt{\sum_{k=1}^{d} y_k^2}}
$$

Cosine similarity ranges from $$-1$$ to $$1$$, but for non-negative data like word counts, it ranges from $$0$$ to $$1$$. A value of 1 indicates identical orientation, meaning the documents share the same relative term frequencies regardless of their absolute lengths.

## 7.0.6. Practical Considerations in Proximity Analysis

Applying proximity measures to real data requires careful preprocessing. Failure to address scale differences and missing values will render the calculated distances meaningless.

### 7.1 Standardisation of Variables

When numeric attributes are measured on different scales, an attribute with a large range will dominate the distance calculation. To prevent this, we must standardize the variables.

The most common method is **Z-score standardization**:

$$
x_k^* = \frac{x_k - \bar{x}_k}{\sigma_k}
$$

where:
- $$x_k^*$$ = standardized value
- $$\bar{x}_k$$ = mean of the $$k$$-th attribute
- $$\sigma_k$$ = standard deviation of the $$k$$-th attribute

Another method is **Min-Max normalization**, which scales values to the range $$[0, 1]$$:

$$
x_k^* = \frac{x_k - \min(x_k)}{\max(x_k) - \min(x_k)}
$$

### 7.2 Handling Missing Values in Distance Calculations

Missing values pose a significant challenge because standard distance formulas require complete vectors. 

A common approach is to compute the distance using only the attributes that are present for both objects, and then scale the result. If $$m$$ attributes are missing, the adjusted distance is:

$$
d_{\text{adjusted}}(x, y) = d_{\text{partial}}(x, y) \times \frac{d}{d - m}
$$

where $$d$$ is the total number of attributes and $$m$$ is the number of missing attributes.

>[!Warning]
> Imputing missing values with the global mean before calculating distances artificially shrinks the distance between objects, creating false clusters. Always adjust the distance metric or use specialized imputation techniques.

## 7.0.7. Applications in Data Mining

Proximity measures are not merely theoretical constructs; they are the operational engine of several core data mining tasks.

### 7.1 Clustering

Clustering algorithms, such as K-Means and Hierarchical Clustering, rely entirely on distance metrics to group similar objects together. The choice of distance metric directly dictates the shape and structure of the resulting clusters. Euclidean distance tends to produce spherical clusters, while Manhattan distance can produce diamond-shaped clusters.

### 7.2 Classification

In instance-based learning, such as the K-Nearest Neighbors (KNN) algorithm, the class of a new object is determined by the majority class of its closest neighbors. The accuracy of KNN is highly sensitive to the proximity measure used and the standardization of the feature space.

### 7.3 Recommendation Systems

Collaborative filtering recommendation systems predict a user's preference for an item by finding similar users or similar items. Cosine similarity is heavily used in item-based collaborative filtering to measure the similarity between item rating vectors, ignoring the different rating scales used by individual users.

## 7.0.8. Example of Computing Proximity Measures

To solidify the mathematical concepts of proximity, we apply the formulas to a concrete scenario involving both numeric and binary attributes.

Suppose:
- Object $$x$$ has numeric attributes $$(2, 4)$$ and binary attributes $$(1, 0, 1)$$
- Object $$y$$ has numeric attributes $$(5, 8)$$ and binary attributes $$(1, 1, 0)$$
- We want to compute the Euclidean distance for numeric attributes and the Jaccard coefficient for binary attributes.

### Step 1: Compute Numeric Euclidean Distance
$$
d_E(x, y) = \sqrt{(2 - 5)^2 + (4 - 8)^2} = \sqrt{(-3)^2 + (-4)^2} = \sqrt{9 + 16} = \sqrt{25}
$$

### Step 2: Finalize Numeric Distance
$$
d_E(x, y) = 5
$$

### Step 3: Identify Binary Matching Categories
Comparing the binary vectors $$(1, 0, 1)$$ and $$(1, 1, 0)$$:
- Position 1: (1, 1) → contributes to $$M_{11}$$
- Position 2: (0, 1) → contributes to $$M_{01}$$
- Position 3: (1, 0) → contributes to $$M_{10}$$

### Step 4: Count Binary Matches
$$M_{11} = 1, \quad M_{10} = 1, \quad M_{01} = 1, \quad M_{00} = 0$$

### Step 5: Compute Jaccard Coefficient
$$
J(x, y) = \frac{M_{11}}{M_{11} + M_{10} + M_{01}} = \frac{1}{1 + 1 + 1} = \frac{1}{3} \approx 0.333
$$

The Euclidean distance for the numeric attributes is **5**, and the Jaccard coefficient for the binary attributes is **0.333**.

## 7.0.9. Conclusions

Proximity measures translate the abstract properties of data objects into quantifiable geometric relationships. The selection of an appropriate metric is not a trivial detail; it fundamentally shapes the behavior of clustering, classification, and recommendation algorithms.

### 9.1 Summary of Proximity Measures

The following table summarizes the primary proximity measures and their appropriate use cases.

| Attribute Type | Recommended Measure | Key Characteristic |
|:---|:---|:---|
| Numeric (Independent) | Euclidean, Manhattan | Sensitive to scale; requires standardization |
| Numeric (Correlated) | Mahalanobis | Invariant to scale and correlation |
| Binary (Symmetric) | Simple Matching Coefficient | Treats 0-0 and 1-1 matches equally |
| Binary (Asymmetric) | Jaccard Coefficient | Ignores 0-0 matches |
| Text / High-Dimensional | Cosine Similarity | Measures orientation, ignores magnitude |

### 9.2 Selecting the Right Measure

>[!Tip]
> Always align your proximity measure with the underlying semantics of your data. Applying Euclidean distance to asymmetric binary data or unstandardized numeric features will yield mathematically valid but semantically disastrous results.
